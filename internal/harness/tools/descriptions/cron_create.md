Create a RECURRING scheduled cron job. Cron jobs run repeatedly on a fixed schedule (e.g. every 5 minutes, every hour, daily at midnight). They are NOT one-shot timers — do NOT use cron_create if the user wants to run something once, after a delay, or at a single future time. For one-shot delayed execution, use bash (e.g. 'sleep 120 && command') instead.

For a legacy shell job, provide `command` and omit `execution_type` (or set `execution_type` to `shell`). For a conversational job that sends an assistant turn into the active conversation, set `execution_type` to `harness` and provide `prompt`; do not provide `command`. The harness job's tenant, agent, conversation, job, and execution correlation fields come from immutable run metadata and are never accepted from model arguments.
